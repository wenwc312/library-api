當你的 HTML 檔案是用 file:/// 方式在瀏覽器開啟，而 API 是在 http://localhost:8080，瀏覽器會
認為這是兩個不同的來源，基於安全性，預設會擋掉JavaScript 從網頁對 API 發出的請求。
這不是你程式寫錯，是瀏覽器的保護機制。

解法是在 Controller 上加一個註解，告訴 Spring「允許任何來源呼叫我」：

@RestController
@RequestMapping("/books")
@CrossOrigin(origins = "*")  // 加這行
public class LibraryController {
    // 其他不變
}

origins = "*" 的意思是「允許所有來源」，這在正式產品上並不安全，
但在你現在練習階段完全沒問題，之後有需要再收緊。

★前後端分離（業界較大型專案更常見的做法）

當專案變大、或是要用 React / Vue 這類前端框架時，業界主流會把前端跟後端拆成兩個完全獨立的專案：
後端：Spring Boot，只負責提供 API（就像你現在寫的）
前端：另外一個專案（React/Vue），甚至部署在不同的伺服器、不同的網域

這種架構下，CORS 就是必須處理的日常議題（不是意外，是常態），因為前後端本來就是分開跑的。
這樣拆分的好處是：前端、後端可以分開部署、分開版本控制、分開讓不同的人負責，也方便前端同時對接多種後端
（網頁版、App版共用同一套API）。

//目前先不採用，等之後想進一步學 React 這類框架時，很自然就會走向「前後端分離」
